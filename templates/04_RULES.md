# 方法论库 · 分层结构与更新纪律

> 本文件规定「**库怎么长、怎么改**」。它管的是**库本身**，不是具体技术问题。
> 一句话：**分层分级 + 按需深入 + 有理有据地改，绝不覆盖**。

---

## 一、要解决的问题

交接上下文是最稀缺资源。若"必读清单"膨胀到几百 KB，每轮"热身"就吃掉大半预算。
⇒ 目标：**必读极小 + 按需深入（像查字典）+ 展开内容不丢（沉淀备查）**。

## 二、五层结构

| 层 | 文件 | 装什么 | 谁读、读多少 |
|---|---|---|---|
| **L0.5 快照** | `00_LIVE.md` | 此刻在做什么 | 压缩后第一个读，全文（≤30 行） |
| **L0 任务书** | `01_TASK.md` | 要干什么 / 铁律 / 坐标 / 读法 | 每轮必读（≤50 行） |
| **L1 索引** | `02_METHOD.md` §0 | 条目一句话摘要 | 扫一眼定位 |
| **L2 条目** | `02_METHOD.md` §x.y | 症状→根因→判据→修法 | 只读被指到的那条 |
| **L3 案例** | `03_CASES.md` | 长案例 / 日志 / 原文 | 溯源时才读 |

**分层判据**：
- 一句话能说清、每次都要守 → **L0 铁律**
- 一句话能说清、只在特定情形需要 → **L1 + L2**
- 需要举例/贴日志/讲推演 → **L3**（L2 只留结论 + 锚点）
- **"我现在干到哪了"** → **L0.5**（覆盖式、≤30 行）

## 二点五、上下文预算（**硬限制**，超限就降级）

**分层靠"每层能一次读完"才成立。任何一层膨胀，"按需深入"就名存实亡。**

| 层 | 硬限制 | 超限怎么办 |
|---|---|---|
| L0.5 快照 | **≤30 行** | 删旧项，只留"此刻" |
| L0 任务书 | **≤50 行** | 细节挪 L2，只留 做什么/铁律/坐标/读法 |
| L1 索引 | **每条 ≤1 行** | 按主题拆分分组 |
| L2 单条目 | **≤20 行** | 展开内容挪 L3，正文只留结论 + 锚点 |
| L3 | 不限 | — |

- **超限 ⇒ 降级（挪到下一层），不要删** —— 删了就真的丢了。
- **自检**：`wc -l` 一跑就知道。**把行数上限写进文件头**，超了立刻处理，别攒。

## 二点六、修剪与归档（防止索引无限膨胀）

索引和条目**只增不减**会拖垮 L1。定期做三件事：

1. **合并**：多条讲同一件事的 ⇒ 合成一条，保留各自"适用条件"（见 §三 并存原则）；
2. **降级**：**长期没被引用**、或**已被上游更普适的条目吸收**的 ⇒ 移入 L3，
   索引里改成一行 `→ 详见 L3#锚`；
3. **标废**：被实证推翻的 ⇒ 不删，标注 `~~已废（依据：…）~~`，因为它记录了"曾经怎么错的"。

> **判据要能执行**：给每条加一行 `最后引用：YYYY-MM-DD`；**超过 N 个月未引用**的进降级候选。
> （别用"感觉没用了"当判据。）

## 三、更新纪律（★ 最重要）

### 3.1 改库前必须做三件事
1. **先查有没有**：grep 索引与关键术语。
2. **若有 → 先问"前人为什么这么写？"** —— 不读完旧条目，不许动笔。
3. **判性质**：

| 判定 | 处置 |
|---|---|
| **真不对**（被实证推翻） | 改，但**留痕**：`~~旧说法~~ → 新说法` + `依据：…` |
| **不同情况**（旧说法在自己条件下成立） | **【并存】** + 写清"适用条件/反例"，**绝不覆盖** |

### 3.2 什么才算"有理有据"
- 必须有**实证**：日志 / 可复现步骤 / 对比数据 / 统计。
- **禁止**：凭一次印象改库；把**个别情形**写成**通则**。
- 判据能落成**一条命令**的，必须写出来。

### 3.3 每次改库必须留痕
- 条目末尾：`> 修订：YYYY-MM-DD · 谁 · 为什么 · 依据`
- **同步更新 L1 索引**（新条目不进索引 = 等于没写）

### 4. 完成态必须显式声明，并做「空转防护」

**自动化不会自己停。** 所以"任务已完成"必须写在 **agent 每轮必读的第一份文件的最顶部**：

```
> # ★★★ 【已完成】YYYY-MM-DD HH:MM · 连续三遍无修改
```

**此后每轮开工读到它 ⇒ 本轮只做一件事：确认没有新问题，然后立即结束。**

- 不重复劳动；
- **不为了"显得有产出"而改已经正确的东西**；
- **不把"完成"改回"未完成"**；
- 若确实发现新问题 ⇒ 才把那行去掉，恢复正常干活。

> **为什么这条要单列**：**空转是浪费，乱改是破坏**。
> 让一个"已经没事可干"的 agent 继续跑，它会**自己找事干** —— 而它找的事往往是把正确的东西改错。

> 注意区分：「三遍无修改」是**允许最终汇报**的闸门，**不是"停掉自动化"的开关**。
> 自动化由人停，agent 不该（也无法）自己停 —— 所以只能靠这条"看到已完成就安静退出"来防空转。

## 四、和 Obsidian 的关系

同类思路（原子化 + 互链 + 分层 + 按需展开），但**读者不同**：
Obsidian 面向人（靠 `[[双链]]` 跳转），**agent 只按索引定位再读那一段**。
⇒ 把"链接"落地为 **索引 + 锚点路径**，比做图谱更省上下文。`[[相关条目]]` 写法保留（人读有用）。
